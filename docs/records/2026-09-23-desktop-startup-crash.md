# Desktop startup/shutdown crash

The supplied September 21 macOS reports show Electron 44.2.0 terminating with
SIGTRAP shortly after launch. The exact Electron Framework UUID matched the
official 44.2.0 symbols: `4C4C44A4-5555-3144-A179-5C2625687460`.

Symbolication resolves the fault to `content::RenderProcessHostImpl` and its
`CHECK(!BrowserMainRunner::ExitedMainMessageLoop())`. The stack creates a
`BrowserWindow` from pending JavaScript work drained during native web contents
cleanup. Desktop startup awaited its UI session and preferences without checking
whether the app had begun quitting.

The main process now tracks shutdown before asynchronous startup begins, checks
after each startup await, disposes a late UI session, and prevents late window
creation or recovery dialogs. A canceled unsaved-editor quit restores normal
window behavior.

The regression harness resolves or rejects the real startup preference read from
a web contents destruction callback during native teardown. Before the fix, the
resolved-read case reproduced SIGTRAP at the same Electron Framework offsets.
After the fix, both cases exit normally with code 0. The September 23 22:08:38
report (PID 70362, parent Codex) was generated by that controlled reproduction.

Validation on macOS ARM64 / Electron 44.2.0:

- Desktop typecheck and development build passed.
- All 147 Desktop unit tests passed.
- Both native startup/shutdown regressions passed.
- All nine notification scenarios passed, including draft preservation, reload,
  minimized-window restoration and recreating a closed window.
- Account sign-in/cancel/catalog/logout and both UI rebuild/recovery scenarios
  passed. Screenshots were inspected.

The running user Desktop was left intact. Relaunch the rebuilt development app to
load the fix; an already-running Electron main process keeps its old code.
