# UX polish of the TUI and Desktop, October 23–24, 2026

The owner asked for every TUI and Desktop surface to be used as a person would, with friction, unoptimised
flows and bugs found and fixed, no regressions, merged into `main`. Three audits drove the apps with the echo
provider and isolated data: the TUI in a private tmux server at 120×40 down to 12×4 (35 findings, T1–T35),
Desktop's conversation (33, C1–C33) and Desktop's shell around it (35, S1–S35). Four lanes fixed them from
`main` `37cf1510` — `tui`, `conv`, `nav` and `settings` — under the standing rule: frictionless, nothing new
opens by itself, no new confirmations or toasts, no layout jumps, quiet precise wording. Each lane was
reviewed independently until a review found nothing to fix; reviews found real problems in every lane, two of
them safety problems, each fixed with a test.

## Fixed

| Area | Change |
| --- | --- |
| TUI approvals | `y`, `n` and a Chrome card's `a` light their chip at once and answer after 300 ms unless the next key shows a message was begun ("yes but…", "no wait"), timed by when the terminal input read the keys. The chip shows `…` and the hint says what is about to happen; Enter or the same letter again answers now, Esc, Ctrl+C, Backspace or Delete take it back. A settling letter answers only the card it was typed at, and a key that sends it acts on nothing else. Calls waiting on an approval or behind it show ⚠ and ○ instead of spinning, batch steps included. |
| TUI drafts and commands | A command that refuses its arguments keeps the line; Ctrl+C on a draft keeps it one undo away and in history; undo answers the Ctrl+- every terminal sends; typos name the real command and the `look` alias is gone. |
| TUI reading | Questions and opened or failed tool output wrap instead of being cut; folds count lines and open with Ctrl+R (rebindable); an answered question shows its answer; the prompt wraps between words and marks hidden rows; `/help` uses the width it has and `/keybinds` names the fixed keys. |
| TUI layout | Filtered dialogs keep their top edge; notices go when they stop being true; terminals below 12×40 keep the conversation (down to 4 rows); the sidebar choice is remembered; the band says "working" until reasoning streams, what Enter does while work runs, and keeps Auto or `--yolo` beside a notice while Review yields to it. |
| Desktop composer | The message box keeps the keyboard through a send (a failed send puts its text back in one place), Enter in an empty box sends nothing, commands typed after Enter wait for the send, Esc in an empty box or File → Stop response (⌘. / Ctrl+.) stops work. The slash menu shows every description; the @ list is as wide as the box; a dropped text file inside the project becomes a mention. |
| Desktop cards | A permission or question card never takes the keyboard from the message box; it reaches the card's container only when nothing has focus, and keys typed there go to the box. Answers fit narrow columns (Deny · Always ▾ · Allow once, Auto behind a divider in the menu, a steady slot). A waiting step no longer says "Running"; single-choice questions answer on click; the open question is named in the box's placeholder. |
| Desktop transcript | An opened step stays where it was clicked, also while a reply streams; tools are named by whole words of their name (an unknown tool by its own); errors lose engine prefixes and exit codes show only when non-zero; diffs carry a +/− gutter and edits link to Review, which shows added and deleted files in one column; one footer per turn; task-list checkboxes, plain table headers, plain outline titles, full-date timestamps, a raised Jump to latest, no double "Thinking", a tinted fork origin, a softer resting composer border. |
| Desktop navigation | A sidebar click or Search pick opens a preview tab (italic) that the next replaces until the chat is used (a draft or chip, work, a waiting request, a double-click, Enter on the tab, reordering); middle-click keeps one. The open chat's row and its project heading (now sticky) stay in view; another project's name opens it without collapsing it; a click or Search pick puts the keyboard in the message box; the chat list is one tab stop and Delete or ⌘/Ctrl+Backspace archives from it; the side panel lets the sidebar go before covering the chat and offers a way back; Search ranks word starts first in every script and lists New chat and Open project first; the sidebar toggle stays put; tabs keep the active one in view with a proper running dot. |
| Desktop settings | Providers lists what is connected with one Connect a provider; Models shows connected providers' models with Show all; Tools are grouped by source and folded parts with readable titles; Steer \| Queue is one control naming its scope and what a reset falls back to; a Search jump marks its row without restyling a button or stealing focus later; search fields share one themed clear button; Projects and Servers use the sidebar's words, `~` paths and a Current tag; definitions name their plugin. |
| Translations | Strings whose English had moved on (the composer placeholder, Steer/Queue, Theme and Appearance, Task notifications, MCP servers and others) are translated again in every language; a test keeps the `@` and `/` a string tells people to type. |

Fixed in passing: the TUI writes `tui-state.toml` atomically and through a link; Settings rows keep their
focus when a list refreshes; a Search jump waits for a loading row's controls.

## Left for a decision

- **Working without a project (S4)**: the Desktop UX brief asks for "Don't work in a project" and a Chats
  group; DESKTOP-PROJECT-MODEL.md says projects are required. Nothing was built.
- **Not changed, by choice**: the server switcher with one server (S22), the signed-out account row (S35),
  a file-tree context menu (S29), Find highlighting in place (C10), the Review mode's name (C17), a retry
  action for retryable errors (C4, no runtime support), a person's own `!` command asking approval (T11),
  Tab switching the agent mid-draft (T16), the TUI's Esc rules and approval chip names (T17, T18), `/export`
  to the temp folder and `/logs` without a log view (T24, T25), the TUI sidebar appearing on the first
  message (T15) and the thread/session/chat mix in its command table (T27).
- **Input mode scope**: Desktop's Steer | Queue now changes the global setting unless the project overrides
  it (it changed the project before). Browser settings still default to the project.
- **Follow-ups**: `permission.requested` carries no call id, so in a parallel batch the TUI can mark a
  still-running earlier call as the one asking; the inherited input mode's source (parent folder or global)
  is inferred; on Desktop a card leaving makes the transcript bounce for a few frames (seen with steps closed,
  not checked against the base); `desktop.spec`'s worktree test (`page.evaluate` aborted) is intermittent
  under a whole-file run.

## Verification

- Method: each lane in its own worktree, reviewed by a reader who had not written it, again after every
  round: `tui` four rounds (plus a fix to its last input-reader commit, reviewed too), `conv` three, `nav` two,
  `settings` three. Reviews found, among others: a settling `y` answering another chat's card after a session
  switch, `n` then Ctrl+Y letting the request run, a card that took the keyboard answering a sentence typed
  for the message box, a chip-only draft lost from a replaced preview tab, Backspace archiving a just-clicked
  chat, Search ranking worse in Chinese, Japanese and Thai, and a Settings jump stealing focus back. The gate
  found two more, both fixed: End right after opening a step could be undone by the step's settling hold, and
  the side chat's place at 1000 px after the sidebar learned to step aside.
- Rust, on the final merge: `cargo test --workspace` 2,364 passed, none failed (2,330 before); `cargo fmt
  --check`, `xtask architecture` and the commercial-boundary check pass; clippy finds nothing in
  `haarness-tui` (with `-D warnings` it stops at lints already on `main` in crates this round did not touch).
- TUI end to end on the final binary with isolated data: 30 tmux scripts pass, among them the permission,
  composer, navigation, queue, first-frame, script-card, side-chat, language, message-browser, input-settings,
  bug-fix, parity, title, todo, history, logs, task-resume, tool-recovery, resource-mention, model, shell-text,
  picked-element, cursor, connection-security, agent-shell-env, compaction-fork, PTY and the long
  `test-tmux.sh`, which was updated for the new Escape, Ctrl+C and thought-row behaviour. The router-profile
  and billing scripts are opt-in (they spend credits) and were not run.
- Desktop: typecheck, 548 unit tests and the production build. The whole Playwright suite (460 tests) on the
  final merge: 404 passed, 35 skipped, 4 failed, 17 not run behind them. `browser-focus` and
  `notifications` need the window to take focus, which a locked screen prevents (they fail on `main` too);
  the outline test and `mcp-servers` "resource tools" failed only inside the whole run and pass alone (the
  latter also 3 of 3 under heavy CPU load). The same suite on `main` `37cf1510` on the same machine: 366
  passed, 6 failed, 35 not run.
- Not verified: the packaged app, Windows and Linux, `haarness-account.spec` and the live Cloud and remote
  scripts (no server, protocol or SDK change in this round).

No paid model calls: the echo provider, fixtures and isolated data throughout.
