# 2026-11-08 Release 0.1.18: Haarness for Chrome from the Chrome Web Store, and starter credits

0.1.18 follows 0.1.17 by a few hours. Haarness for Chrome installed from the Chrome Web Store can now reach Haarness,
and setup offers the store first; new Cloud accounts' free starter credits are named and paid with.

## What changed

- **Haarness for Chrome from the Chrome Web Store**: the store listing gives the extension its own ID, which the host
  manifest did not allow, so a store install could not start Haarness. Setup now registers both IDs and sends people
  to the listing (Desktop's Open Chrome Web Store button, the link in the CLI and TUI) instead of Developer mode and
  Load unpacked; the unpacked copy is still put in the data folder for people who load it by hand and for policy
  installs. The release skill uploads each release's extension to the store.
- **Starter credits**: a new account's free starter credits are counted as able to pay, named Starter credits in
  /billing, `haarness account --billing` and Desktop's account dialog, and an account without a plan is never told to
  turn on overage; refusals offer the trial, credits or a plan. `haarness login` says Cloud is ready with them.
- **Usage statistics**: end-to-end scripts no longer count as people's installs or failures.
- **Repository**: Python bytecode committed by a script change is removed and ignored.
- **Router** 0.1.18 (version only). **Cloud**: Haarness 0.1.18 in Cloud workspaces, router 0.1.18.
- **Phones**: Android 0.1.18 (version code 8) built with the starter-credits screens; iOS keeps 0.1.17 in App Review,
  so its starter-credits change waits for the next submission.

  writes a host manifest allowing both the unpacked and the store extension IDs.
