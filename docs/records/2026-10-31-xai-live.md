# xAI, live — 2026-10-31

xAI had never run live (no sign-in in the [2026-10-10 audit](2026-10-10-model-support.md)). Signed in with xAI's
OAuth, every local layer was run against its API, as in the [OpenRouter](2026-10-31-openrouter-live.md) and
[DeepSeek](2026-10-31-deepseek-live.md) runs. Haarness Cloud does not reach xAI with a person's sign-in (its own
xAI models go through OpenRouter), so Cloud was not part of it; a remote chat on this computer was.

xAI's `/models` lists 14 models: eight chat models and six image and video generators (`grok-imagine-*`).
`/language-models` lists only the chat models, with their input (text and images, for all of them) but no context
window; `/models` has context windows, prices (in hundredths of a cent per million tokens: 12500 is $1.25), a
long-context tier from 200K prompt tokens, and each model's effort levels (`capabilities.reasoning_effort`).

## What was wrong

| Finding | Effect | Now |
| --- | --- | --- |
| Discovery read `/models` alone. | The six image and video generators were in the picker as chat models with tools; Grok 4.6, 4.5 and 4.20 had raw ids, no price and no image input; Grok 4.3 and Grok Build were marked text-only. | Chat models only, with images from `/language-models` and context, prices with the long-context tier and levels from `/models`; Grok 4.3 offers `none` to `xhigh`. Names for 4.6, 4.5, "Grok 4.20" and "Grok 4.20 Reasoning". |
| `grok-4.20-multi-agent-0309` answers chat completions with 400 "Multi Agent requests are not allowed on chat completions"; it is served on the Responses API. | Every turn on it failed. | Left out of the picker. |
| That refusal is a bare JSON string. | Read as "HTTP 400 Bad Request", without the reason. | A plain-string error body keeps its words (any provider). |
| A sign-in token xAI refuses before its stated expiry was never renewed. | "Connect xAI again", although the refresh token could renew it. | Renewed once and the request sent again; only a failed renewal asks to sign in. |
| Saving credentials replaced `auth.json` with a new file even when it was a symlink. | A linked store (a dotfiles manager; `scripts/test-models-live.py --auth-file`) lost every renewal: the new tokens went to the replacement, the linked file kept spent ones. | Saved in the file the link names; the link stays. |

The last row cost this run its own xAI sign-in: the renewal test above ran before the fix, through a linked store,
so the renewed tokens were lost and the saved refresh token is spent. The access token lasts until it expires
(about six hours); then xAI needs signing in again.

## Live verification

`scripts/test-models-live.py` on xAI with OAuth: Grok 4.7 (all, at `low`, `xhigh` and `none`), Grok 4.3 (all, at
`low`, `xhigh` and a missing level), Grok Build 0.1 (all) and Grok 4.20 Reasoning (all), where all is tools over two
turns, reasoning, images, a workflow agent's structured output and cost.

Recovery through a fault-injecting proxy in front of xAI: a 503 is retried and answered; a 429 fails with xAI's
words; a refused token is renewed and the request answered; a stop during reasoning keeps it and the next message
is answered; one chat moved Grok 4.3 → Claude (Anthropic API) → DeepSeek Flash → Grok 4.7 with a read tool call
each time.

Surfaces: the terminal UI (the seven chat models by name with prices and long-context tiers; a tool turn on Grok
4.3 with its thinking and $0.02), `serve --daemon` with `run`, `sessions list` and `stats` (both turns priced), and
haarness.ai driving a chat on this computer: "xai grok 4.3" found the model, and a read tool call answered.

## Left for a decision

- The haarness.ai model picker offers its own reasoning levels (Auto to Max) rather than the model's; Haarness
  picks the nearest level the model has.
- The multi-agent model needs the Responses API, which Haarness's xAI provider does not speak.
