# 2026-11-08 Release 0.1.17: computer use, steadier long turns, and fixes for the failures people hit most

0.1.17 is the first release from `main` since 0.1.15. Agents can now use the apps on a Mac, with a person approving
each app; long turns, tool history and Undo hold up better; and the failures telemetry showed most often (tools on
Windows, local models, direct provider keys, custom endpoints, web fetches and a new account's first Cloud turn) are
fixed at their causes.

## What changed

- **Computer use**: an agent can see this Mac's screen and work in its apps. Each app is approved by a person, once
  or for good; an agent cannot widen its own reach; typing and Escape are safer; a paused agent says so. Yolo mode
  approves it as it approves everything else, and the phones show what the agent wants to do in the person's
  language.
- **Long turns**: compaction keeps the person's latest request and the turn's newest calls and cuts oversized tool
  outputs instead; tool history stays in order; shell reading is safer; Undo works through large files and names the
  files it left as they were; scheduled runs finish their work; one host per computer; MCP servers and config saves
  are sturdier.
- **Windows**: tools read long, BOM, UTF-16 and mixed-ending files; commands run in Git Bash when it's installed;
  Windows paths are asked about; two saves creating a config folder at once both succeed.
- **Local models**: Ollama chats get a 32K context instead of a prompt silently cut to 4K, a prompt that still does
  not fit is refused in plain words, models without tool support say which model to pull, and numbers a small model
  writes as text reach its tools as numbers.
- **Providers**: refusals say what to do; a model whose account ran out of credit says so at once; new Gemini
  connections start on Flash; calls moved between providers keep valid ids; broken tool arguments are answered with
  an error the model can correct, and arguments encoded twice are read as the object they hold; custom endpoints are
  checked when they're set up; browser tools go only to chats a browser can serve.
- **Web fetches**: pages agents ask for are read, and a failed fetch says what to try.
- **New accounts**: a new Haarness account hears how to start before its first Cloud turn, and its new chats start on
  a provider that can answer.
- **Editors**: an ACP agent started with `-m provider/model` runs on that provider.
- **Router**: 0.1.17. A provider account out of credit says so and operators see why requests fail; a chat moved to
  Claude keeps working; a too-long conversation says so; older GPT models read images.
- **Cloud**: Haarness 0.1.17 in Cloud workspaces; the managed router leaves a prompt room in the model's window and
  says when to try again after a busy or per-minute refusal; the pricebook keeps out models it cannot serve (free
  OpenRouter variants, windows under 32K, models with no live endpoint), so about a dozen tariffs leave the list; a
  new account is told it has never had credits.
- **Phones**: iOS 0.1.17 (build 8) and Android 0.1.17 (version code 7): computer use cards, Retry for a chat that
  could not be read, a new workspace's typed task kept until it starts, Undo's notice.

  it on 0.1.17; the 0.1.16 CLI showed "Haarness 0.1.17 is available" on its home screen and `haarness --update`
  installed it.
- `install.sh` and `install-router.sh` from haarness.ai (and from staging before prod) installed CLI 0.1.17 (`doctor`
  runs) and router 0.1.17, which listened and answered `/healthz`.

  Notarized Developer ID.
- The Windows installers and CLIs downloaded from haarness.ai are the bytes `check-windows` read (same SHA-256).
