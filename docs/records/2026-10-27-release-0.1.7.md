# 2026-10-27 Release 0.1.7: the first update from a self-updating release

0.1.7 ships Desktop's Windows update path (its servers stop cleanly before the setup replaces them, and the setup's
outcome is reported; see [Updates on Linux and Windows](2026-10-27-linux-windows-updates.md)) and a fix by another
session (a photo sent without text reaches Claude through Cloud). It is the first release that installed copies of the
previous one (0.1.6) find and install by themselves, and that was proven on every platform it could be, against
staging and then production, with copies of 0.1.6 installed by `install.sh` as people install them.

## 0.1.6 → 0.1.7, on staging, then on production

- **macOS**: the 0.1.6 app from `install.sh`, launched through LaunchServices as a person launches it and driven over
  its remote-debugging port, found 0.1.7, downloaded and verified it (ready in 10 s on production), and
  **Restart to update** replaced it and opened 0.1.7: "Notarized Developer ID" (STACK FORWARD LLC, J63GND4Q8A), the
  team requirement satisfied, nothing left beside it, an empty updates folder, About "You are up to date".
- **Linux**: `FROM_VERSION=0.1.6 scripts/test-linux-update.sh` (new mode, no stand-in): the 0.1.6 AppImage from
  `install.sh`, in a Docker desktop session without libfuse2, updated from the release service to 0.1.7's exact file,
  reopened with its flags and ran 0.1.7.
- **TUI**: the 0.1.6 CLI from `install.sh` showed `↑ Haarness 0.1.7 is available. · haarness --update` on its home
  screen, and `haarness --update` installed 0.1.7.

## Found on the way

The first macOS rehearsal launched 0.1.6 the way the earlier tests did, through Playwright's `executablePath`: the
app said it cannot replace itself and offered the installer. A notarized app Gatekeeper has seen is protected by App
Management (`com.apple.macl`, `com.apple.provenance`): only the app itself, and processes it starts, may modify it,
and an app started directly by a test answers to the test's terminal instead. Desktop read that correctly and fell
back as designed; launched as people launch it, it updates itself. The release skill now says to launch through
`open` for this proof, and DESKTOP.md says a copy started from a terminal may offer the installer.

## Not proven

Windows: neither 0.1.6's update to 0.1.7 (0.1.6 runs the setup directly) nor the new helper path has run on a
Windows machine; the helper is proven under PowerShell 7 with stand-ins.
