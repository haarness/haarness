# 2026-11-02 Release 0.1.16: Windows signed by Stack Forward LLC

0.1.16 is 0.1.15 with one change: the Windows packages are signed, and Windows Desktop takes an update only from the
publisher that signed it. Every other platform is rebuilt from the same code with the new version number. `main`'s
unreleased work is not in it; the next release from `main` is 0.1.17.

## What changed

- **Windows signing**: the installer, the Desktop app, the CLI, Haarness Router and every program the installer
  carries (the installer's own plugins, the uninstaller, Electron's DLLs) are signed with Stack Forward LLC's
  publicly trusted certificate profile and an RFC 3161 timestamp. Programs other vendors ship (Bun, Microsoft's
  DirectX compilers) keep their own signatures.
- **Windows Desktop updates**: a signed Desktop reads its own publisher and installs an update only when the new
  setup is signed by the same publisher, as macOS Desktop does with its team's signature. One signed by anyone else
  or not at all is refused, and the window names why. An unsigned build (a local one) keeps updating as before.
- **Router**: 0.1.16 (version only).

## Proof

- The Windows installers and CLIs downloaded from haarness.ai are the bytes `check-windows` read (same SHA-256),
  and `osslsigncode verify` against `scripts/authenticode-roots.pem` accepts each: signer `CN=Stack Forward LLC,
  O=Stack Forward LLC, L=Koto-ku, ST=Tokyo-to, C=JP` through Microsoft ID Verified CS AOC CA 03 and Microsoft ID
  Verified Code Signing PCA 2021, with a verified Microsoft timestamp. Staging served the same signed files.
- Production, 0.1.15 → 0.1.16: the macOS app launched through LaunchServices offered Restart to update, installed
  0.1.16 and reopened; `FROM_VERSION=0.1.15 scripts/test-linux-update.sh` replaced the AppImage in place and reopened
  it on 0.1.16; the 0.1.15 CLI showed "Haarness 0.1.16 is available" on its home screen and `haarness --update`
  installed it.
- `install.sh` and `install-router.sh` from haarness.ai (and from staging before prod) installed CLI 0.1.16
  (`doctor` runs) and router 0.1.16, which listened and answered `/healthz`. The served `install.sh` matches this
  repository's byte for byte, and `install-router.sh` differs only in its default product.
- The DMG downloaded from haarness.ai with a browser's quarantine mark: Gatekeeper accepts it and the app inside as
  Notarized Developer ID.

## Not proven

Windows Desktop installing or updating on a real Windows machine (the publisher check is covered by unit tests
only), SmartScreen's verdict on the signed installer (a new certificate starts without reputation), Windows arm64
code anywhere, and Linux Desktop on a real machine.
