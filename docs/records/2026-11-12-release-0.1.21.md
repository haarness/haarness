# 2026-11-12 Release 0.1.21: messages sent again run once, editors keep their MCP servers, Claude Code agents and skills as written, and computer use behind the window

0.1.21 is the first release since 0.1.19. 0.1.20 was built on 2026-11-11 but never published, so everything it held
reaches people now, together with the work since. Every surface is part of it: CLI, Desktop, Haarness Router, Haarness
for Chrome, Haarness Cloud with its workspace image, and the phones (iOS submitted for review, Android bundle built).

## What changed

- **Sending again**: a message sent again after a lost answer (a phone or the web chat behind the relay, a dropped
  connection) is stored and run once. The server takes a steered message's request id as used, runs a steer its turn
  never read once when it is sent again on an idle chat, and settles such a steer after a restart or shutdown instead
  of adding it to every later request; one notice asks to send it again. iOS, Android and the Cloud web chat keep a
  message's request id across Retry, leaving the chat and coming back; a message written again is a new one.
- **MCP**: servers added through the API or an editor survive project reloads; an editor's servers are shared between
  its windows on a chat, come back after the project's server restarts, keep their Always answers, and go once no
  editor process uses them (even after a kill). A tool that ran is no failed call when its server shapes the answer
  slightly wrong; `haarness mcp` commands configure the entry in force. MCP servers recover from restarts and lost
  sign-ins, and their images reach the model shrunk.
- **Editors over ACP** follow the project's server when it restarts or is replaced by a newer build, and see each
  call's files, edits and how full the context is.
- **Agents and skills** behave as Claude Code writes them: `maxTurns`, `skills` preloaded into an agent's prompt, an
  agent allowed bash keeps its background-command tools, a `Bash(...)` pattern in `tools` holds the agent to it, fenced
  ```` ```! ```` blocks and `${CLAUDE_PLUGIN_DATA}` in skills; a skill the model loads never raises an approval card
  for its commands. A continued subagent keeps its agent and model; a subagent's own tasks stay in the foreground.
- **Skills stay visible** to the model while lazy tool loading defers other tools, in a list kept within a budget.
- **Plugin marketplaces** can follow a branch or tag (`…#release`, `owner/repo@v2`); adding one again at another ref
  brings its installed plugins along; a plugin that could not update says how to try again.
- **Computer use** works in an app behind the person's window without taking their pointer or front app, with fewer
  fixed rules, Auto's reviewer answering it, and terms version 2. Only a person raises approvals, answers an agent's
  requests and opens its terminals, however Haarness is named or reached.
- **Providers**: the daemon log names each refused or failed model request by its provider's request id; ChatGPT's
  Ultra level and OpenAI's unfinished responses, Amazon Bedrock with Claude 5.5, Llama and AWS CLI sign-ins, and tool
  calls shaped by other agents' habits no longer fail turns; failed turns on Gemini, custom endpoints and Ollama go on
  or say why.
- **TUI**: PHP without `<?php` is coloured, a second paste of a folded block right behind its chip opens it, tabs are
  drawn and copied whole everywhere, and long command outputs no longer slow typing.
- **Desktop**: right-click spelling and Cut/Copy/Paste, comments on reply text, a blocking Stop hook continues the
  turn; updates move a busy project off an earlier build once its work is done, remove staged copies whole, and
  Restart installs the newest version.
- **Router** 0.1.21 (version only). **Cloud**: Haarness 0.1.21 in Cloud workspaces, router 0.1.21, the web chat's
  send-again fixes, and `install.sh` names a Desktop of another version left open.

## Proof

- Production, 0.1.19 → 0.1.21: the macOS app launched through LaunchServices installed 0.1.21 itself and reopened;
  `FROM_VERSION=0.1.19 scripts/test-linux-update.sh` replaced the AppImage in place and reopened it on 0.1.21; the
  0.1.19 CLI showed "Haarness 0.1.21 is available" on its home screen and `haarness --update` installed it.
- The served `install.sh` and `install.ps1` match the repository's on staging and prod, the router variant by its one
  line.

## Not proven

Windows Desktop on a real Windows machine; Linux Desktop on a real machine; a Cloud workspace started from the new image
on prod; the phones' send-again behaviour against a computer on 0.1.21 through the real relay (proven against a
stand-in relay); Haarness for Chrome 0.1.21 from the Chrome Web Store (until the owner uploads it and review passes).
`scripts/test-linux-update.sh` reports success even when its container step fails (its exit status is lost in a pipe).
