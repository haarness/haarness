# 2026-10-30 Release 0.1.12: remote access for the whole computer in one click

0.1.12 puts remote access for the whole computer in Desktop's title bar. One click makes every project on the
computer reachable from the Haarness phone apps and any browser signed in to the same account, with no code, link or
pairing; another click turns it off. `/remote-control` keeps sharing a single chat, with its link and QR code.

## What changed

- **Remote access** (Desktop): the title bar's control used to share the open chat; it now turns on the account's
  host connector for the whole computer, routed through Desktop's chat home so the computer is reachable with no
  project open. Signed out, a click opens the sign-in and turns access on once it lands. The dot is green while on,
  pulses while connecting and turns red with the reason when the connector gave up. Access stays on when the window
  closes, comes back when Desktop starts (with retries while the network comes up) and restarts a connector of another
  version; off keeps the registration, so phones keep the computer, shown offline. Signing out or switching accounts
  stops the connectors of the account left (Desktop and `haarness logout`). An organization account's tooltip says
  its members can open the computer too.
- **Gateway**: Cloud's requests reach a project whose server already runs through that server as it runs, whatever
  its project configuration setting, instead of restarting it; through the chat home Desktop and the phone kept
  restarting each other's server. Cloud's folder browser starts in the home folder when the computer is reached
  through the chat home.
- **Status**: a moment without Cloud is not shown as a problem; a running connector reads as connecting.
- **Docs and Cloud app** (Cloud): the remote control page leads with the Desktop control, found by its name in all
  seventeen interface languages; the Connect a computer guide and an offline computer's page say to turn it on.
- **Router**: 0.1.12 is a version bump only (tag v0.1.12 = haarness-router 57baa9b).

## Proof

- Before the release, the worktree build against production: Desktop's control on and off, with the iPhone app in the
  Simulator (the computer under Hosts, a new chat in its project answered from this computer, folder browsing from
  the home folder) and the web app in Chrome (the Desktop chat continued from the browser, the computer shown offline
  once turned off), with no project server restarted (`e2e/remote-access.spec.ts`, live mode, which fails without the
  gateway fix).
- After the release, the released, notarized 0.1.12 app against production: its title bar turned remote access on;
  the iPhone app listed the computer as online on v0.1.12 with its project, and a new chat sent from the phone ran on
  this computer and answered; turned off, the phone showed it offline at once. No project server was restarted.
- The remote control docs: the site search finds the page by the feature's name in all seventeen interface
  languages on a local build of the deployed pages, and in Chinese on haarness.ai; a search for remote access opens
  at the new steps.
- Staging: `install.sh` from staging installed CLI 0.1.12, whose remote access request answers signed out.

## 0.1.11 → 0.1.12 on production

- **macOS**: a signed 0.1.11 app launched through LaunchServices offered Restart to update, installed 0.1.12 and
  reopened (`install result ok`).
- **Linux**: `FROM_VERSION=0.1.11 scripts/test-linux-update.sh` replaced the AppImage in place with the release's file.
- **TUI**: the 0.1.11 CLI showed the notice on its home screen and `haarness --update` installed 0.1.12.

## Not proven

Windows and Linux Desktop remote access on a real machine (the same code; macOS only), Windows updates on a Windows
machine, an organization account's tooltip with a real organization (unit tests only), signing out and switching
accounts in the running app (unit tests of the bridge; the end-to-end spec covers the signed-out click), and the
Android app (no change; not run). The phone apps' empty Hosts screen still names only `haarness remote enable`.
