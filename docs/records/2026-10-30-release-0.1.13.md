# 2026-10-30 Release 0.1.13: agents' shell commands in the background

0.1.13 lets agents run shell commands in the background. A dev server or a long test run starts there
and the conversation carries on; a command that runs past a minute moves there by itself in a chat a client follows,
and the chat is told how each one ended, which starts the agent's follow-up. Every client shows them the same way:
an **In background** row with its state, its live output and a Stop.

## What changed

- **Commands in the background** (runtime): `bash` takes `run_in_background`; new tools `bash_output` (list, read
  from a cursor, wait for an end, a quiet spell or a printed line) and `bash_stop`, offered wherever `bash` is. A
  foreground command moves after `execution.shell_move_after_ms` (60 s) only where a client follows the chat
  (`followsBackground`: Desktop, the terminal UI, the web chat, the phone apps); SDK scripts, ACP, `haarness run` and
  schedules keep their deadlines. Ends are delivered like background subagents' results; a long-lived command never
  holds the chat's "done". Stop during a reply leaves background commands running. A restart marks a running command
  cut off without starting a turn. Routes `/v1/threads/{id}/commands…` and `/v1/commands/active`, events
  `command.updated` and `command.output`, item `command_state`, capability `background-commands.v1`; SDKs updated.
  `sleep 300 & echo started` no longer holds a call until its deadline, and a character split across output chunks
  stays whole.
- **Desktop**: the row's badge, time, live output and Stop; Send to background on a running command or subagent (and
  in the File menu); a title-bar count opening **Still running**; a ring on a chat whose only work is in the
  background. **Terminal UI**: rows, Ctrl+X (rebindable) to send work to the background, a full-screen output view,
  `/tasks` and a sidebar section. **Web chat**: rows with output and Stop; controls a phone can reach.
- **Fixes**: a connection that breaks after the model began answering is recovered; a project no longer decides the
  person's own Claude Code files (and editing them reloads again); Gemini 2.5 keeps room for its answer under a small
  output limit (also in Haarness Router); shell readings see the command behind `time`, `coproc`, `env -C`, `sudo -D`,
  `sudo --login`, shortened or quoted options; web fetch checks every redirect on the host against its rules;
  instruction globs and the `glob` tool end on link loops.
- **Cloud**: workspaces stay awake while an agent's command with a time limit runs (until that limit), open-ended ones
  for at most an hour after the workspace was last used, and a workspace caps background commands at an hour by
  default. **Router**: 0.1.13 (v0.1.13 = haarness-router 466f8c6) with the Gemini change.
- **Phones**: iOS build 5 and Android 0.1.13 (versionCode 5) show commands in the background; the plan stays in reach
  in short windows.

## Proof

- Production, before the publish: a new Cloud workspace on the new image ran runtime 0.1.13 with
  `background-commands.v1`; an agent started `sleep 20; echo proof-done` in the background (limit one hour, from the
  workspace defaults), its reply finished without holding the chat, and the command's end (exit 0, `proof-done`)
  started the agent's follow-up, which reported it.
- Staging: `install.sh` installed CLI 0.1.13 and router 0.1.13; the served installers match this repository's.
- 0.1.12 → 0.1.13 on production: the macOS app launched through LaunchServices offered Restart to update, installed
  0.1.13 and reopened (`install result ok`); `FROM_VERSION=0.1.12 scripts/test-linux-update.sh` replaced the AppImage in
  place; the 0.1.12 CLI showed the notice on its home screen and `haarness --update` installed 0.1.13.

## Not proven

Windows and Linux Desktop on a real machine (the same code; macOS only), Windows updates on Windows, the Cloud relay
to a remote computer with the new routes (the gateway forwards them; phones were run against a local server), and the
phone builds on a real device (simulators and an emulator only).
