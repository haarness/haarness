# 2026-10-30 Release 0.1.14: a larger app icon, and plainer words about what Haarness does

0.1.14 is a small release. The app icon's H is drawn larger, so Haarness holds its own beside other apps in the Dock,
the taskbar and app menus; a provider's refusal reads in its own words; and a Haarness Router's models show the
router's mark. Under the website's headline, and at the top of the README, Haarness now says what it does for the
person reading.

## What changed

- **App icon** (Desktop on every OS, the brand kit): the H spans 55% of the tile instead of 42%, centred as before,
  in the dark and light icons and everything exported from them (PNGs, icon.ico, the Linux icons). Haarness for
  Chrome carries it from this build.
- **Refusals**: a provider's 4xx answer with a reason of its own reads as that reason, naming the provider when the
  turn knows it ("Haarness Router rejected the request: Provider groq is not set up …"); the status line and code
  stay in the log.
- **Desktop**: models from a connected Haarness Router show the router's mark in the model pill and wherever the
  provider's icon appears, not Haarness Cloud's.
- **Website** (Cloud): the headline stays "Power your work with the best AI harness."; the line under it now reads
  "Haarness is an AI assistant that does the work, not just the talking. You see every step, it asks before anything
  that matters, and it runs on your computer or in the cloud." The meta description, brand boilerplate, link-preview
  image and web app manifest follow, in all 17 languages, and Korean headings break only between words. (A new
  headline, "Tell it what you need. It gets it done.", was live for about an hour and taken back at the owner's
  request.) The README opens with the same sentence.
- **Router**: 0.1.14 (version only).
- **Phones**: iOS build 6 and Android 0.1.14 (versionCode 6): Hosts with no computer yet leads with Desktop's Remote
  access.

## Gate

Format, the boundary check, `test-release-publish.py`, the router's 102 tests, Desktop's typecheck, the Cloud web
tests (566) and its public-site browser tests. The machine was shared with many other sessions' servers and builds
(load average up to 120 on 18 cores), and timing tests showed it:

- Rust: 2,988 passed and 5 failed in the full run. Four passed when run alone. The fifth,
  `a_client_that_reads_nothing_for_a_while_keeps_its_place_and_every_word`, times out at 30 s here, and the 0.1.13
  source fails it the same way on this machine today; 0.1.13's gate passed it. An earlier run also failed
  `serve_takes_a_free_port_only_when_the_default_one_is_taken` (another test took the freed port), which passed three
  times alone.
- Desktop unit tests: 706 of 708; the two image-recheck tests that failed count reads against a clock and passed
  alone in two of three runs. Neither the image code nor the event stream changed since 0.1.13.
