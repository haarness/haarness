# 2026-10-27 Release 0.1.8: plain errors on every surface

0.1.8 ships the plain error words that came after 0.1.7: a computer's gateway that cannot reach its project's server
tries once more, then answers `project_server_unavailable` instead of a bare 502, and Desktop and the TUI say "Your
computer couldn't answer" instead of HTTP or cancellation words. The same day, Cloud, the iPhone app and the Android
bundle went out with the same wording, so every surface carries it.

## Release

Source 1274e04c (tag v0.1.8), stable channel, release ID 01a17bb9-dd7e-7162-853c-72f50bc217cb; GitHub release with
19 assets, sizes and SHA-256 verified. Gate: Rust workspace 2,602 tests, Desktop 633, SDK 32,
`test-release-publish.py`, the commercial boundary check. All six platforms built on this Mac: macOS natively in 21
minutes (signed, notarized, stapled; Gatekeeper accepted both DMGs, the apps in them and the apps in the ZIPs),
Linux and Windows in Docker in 40 minutes with `CARGO_BUILD_JOBS=2` and 36 platform checks passing; Windows unsigned,
as for 0.1.7.

Cloud 20261027-2ee37d4 (the web's plain errors) with workspace image 20261027-1274e04-2ee37d4, staging then prod
(haarness-deploy f1930a5, daa249a). Cloud gate: 126 Rust tests (the 9 billing route tests that failed with "out of
shared memory" on the local Postgres pass with `--test-threads=2`), web 410.

- **macOS**: the 0.1.7 app from `install.sh`, launched through LaunchServices (`ls-update.mjs`), offered

- **Linux**: `FROM_VERSION=0.1.7 scripts/test-linux-update.sh` replaced the AppImage in place and ran 0.1.8.
- **TUI**: the 0.1.7 CLI showed `Haarness 0.1.8 is available.` on its home screen, and `haarness --update` installed

## Found on the way

- A workspace image change alone does not restart Cloud's pods, and running pods keep the old
  `HAARNESS_CLOUD_DEFAULT_IMAGE` until they restart: `deploy.yml -e restart=true` after changing only
  `workspace_version`.
- The iOS export failed with "Copy failed" because Homebrew's rsync was first on PATH (Xcode's packaging expects
  `/usr/bin/rsync`); run `xcodebuild -exportArchive` with `/usr/bin` first. The App Store Connect API key in
  `notarization.env` cannot cloud-sign, so the upload uses Xcode's signed-in account.

## Not proven

Windows updates on a Windows machine, a Cloud workspace started on the new image, the Android bundle on Play.
